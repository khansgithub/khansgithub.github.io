## [kakao-agent]

### finally a decent day

- set up + deployed the automation for auto-sending messages using `agent-messenger`
- used AI to update the kofi-injector extension to pull data from the `newsBotSummaries` repo

#### setup

the first things to install were:
	- termux + tasker plugin
	- Automate

on termux, we had a bunch of other things to setup and install:
	- `termux-setup-storage`, allows termux to interact with the user folders, mapped under `~/storage`
	- `git curl clang make glibc-repo python jq glibc-runner node bun`, various dependencies for `bun` and `agent-messenger`
	- set up the `bun` wrapper from `https://github.com/Happ1ness-dev/bun-termux.git`
	- `node-gyp` using bun (crucial for `agent-messenger`)
	- and finally the holy grail, `bun install agent-messenger`
	- set up folder structure and files with `install.sh` - copies `automate-entry-point.sh` into `~/.termux/tasker` and the send/login scripts into `~/kakao-news-automation`
	- set `run-commands` permission for termux
	- import the `flo` workflow into Automate

the flow itself:

- the desktop app builds summaries and pushes them to github on a date-named branch (`newsBotSummaries`)
- the custom android app pulls branches, checks out the latest one, copies files to a specific folder on the phone
- an [Automate](https://llamalab.com/automate/) flow runs a termux script on schedule that takes the oldest file and sends it via `agent-messenger`
- the android app also has a login screen that calls termux to run agent-messenger auth, using `am broadcast` to return the passcode

#### kofi
after setting it all up, we suddenly realised that we broke something else. the previous workflow for posting the news on to the kofi blog involved copying the messages directly (from where they were stashed in a kakao group chat) to the kofi-inject extension. however now that the posts are directly sent to the main chatroom, this no longer works. the full summaries don't live in chat anymore, they're in the repo now.

the next step was:
	- update the chrome extension to pull files from the repo branch

i had no clue if a chrome extension could even use git — i figured it either required working with the github api or a git client. i asked an AI agent to help me build this. we went with the git client and ai suggested a wasm-based one.

the first stumble was on cors. the extension can't directly send requests to github. ai suggested we move the logic to a service worker. i learnt service workers bypass cors issues!

as i was watching the agent do its thing, we started getting errors. the wasm git client depended on node.js's buffer type, but node types don't exist in extensions. the ai suggested to polyfill the buffer function. i said okay and just watched.
another error - looks like there's another missing node class. ai suggested to polyfill it - sure.
eventually, it hit me that this probably isn't the best way forward.
i asked ai if there's a better solution than polyfilling. it suggested the package `buffer` npm package. however noted that the package is a CJS module, and not UMD. i had no clue what that meant. i looked it up, and it seemed like they were just different module wrappers.
ai seemed to see this as a total blocker. i blindly asked if a CJS module could be converted to UMD, and to my surprise it seemed to be a great solution. the agent suggested using `rollup` to convert the module,

now the kofi-injector extension is about to pull the branches from the github repo, and fetch the individual news articles, to embed into the post!

admittedly, i have no clue how this git client implementation works in the service worker. but it works well!

### outcome

the original workflow was heavily dependent on the user having to remember to send out the messages on time. when curating a brand and audience, it's paramount to ensure high engagement with your audience. this slow started to build stress - where every message could make or break a member leaving or joining the chatroom.

this automation kills the need for constant vigilance and the mental load of manually copying and pasting a message to a group chat 8 times a day. while it's not (yet) a closed loop one-touch automation cycle, it's patched together the biggest moving pieces in this process.
